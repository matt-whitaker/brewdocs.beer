# packages/e2e

Package-specific guidance. See the repo-root `CLAUDE.md` for universal rules (commands, dependency graph, the _Legend_ of field labels, contributing). Italic cross-references name a section that may live in another package's `CLAUDE.md` — most app subsystems are in `packages/app/CLAUDE.md`.

**Purpose.** Playwright functional-test harness — the browser-driven suite that exercises the real app (via `packages/app`'s dev server), as opposed to lint/typecheck/build which only prove the code compiles.
**Where.** `playwright.config.ts` (baseURL, `webServer`, chromium project), `tests/*.spec.ts` (one spec per screen/flow), `tests/helpers.ts` (only the handful of queries not already covered by Playwright's built-in locators).
**Surface.** `npm run test:e2e -w packages/e2e` runs the suite headless; `npx playwright test --ui -w packages/e2e` (or `cd packages/e2e && npx playwright test --ui`) for the interactive runner while writing specs; `npx playwright show-report` (from this directory) opens the last HTML report.
**Invariants.**
- ⚠️ `webServer` in `playwright.config.ts` auto-starts `npm run dev -w packages/app` (with an explicit `cwd: "../.."`, since `-w` only resolves from the monorepo root, not from `packages/e2e`) and waits on `http://localhost:5173` — the app's own `predev` symlinks `public/kb → ../../kb/dist`, so don't add a separate kb-serving step here. `reuseExistingServer` is `!process.env.CI`: locally it reuses a dev server you already have running (fast iteration); in CI it always starts a fresh one.
- ⚠️ The `webServer` **explicitly forces `VITE_DEV_TOOLS=false`** (via `webServer.env`) — don't remove it. `packages/app/.env.development` sets it *true*, so a plain `npm run dev` renders the TanStack devtools overlay, which injects hidden `status:`/`statusCode:` nodes that break substring locators (`getByText("Status")` → strict-mode multiple-match) and can shift layout / intercept clicks. A process env var overrides the `.env` file. ⚠️ This only applies when Playwright *starts* the server; locally with `reuseExistingServer`, a dev server you already have running keeps whatever `VITE_DEV_TOOLS` it launched with — so run your manual dev server with `VITE_DEV_TOOLS=false`, or let Playwright start it.
- Every test gets a **fresh browser context** (Playwright's default) — no shared IndexedDB/localStorage/sessionStorage between tests, so no `/?purge=true` dance is needed for isolation the way a manual browser session would need it.
- Prefer `getByRole`/`getByText` (Playwright's built-in locators) over custom query helpers — `tests/helpers.ts` should only grow when a query has no reasonable accessible-role/text equivalent (e.g. `activeTabName`, since "the currently active PanelSwitcher tab" isn't a single accessible name).
**Gotchas.** ⚠️ This package's `test` script (`eslint .`) is what `npm test -ws` runs as part of Verify — that's a **lint-only** check, not the Playwright suite. The actual browser run (`test:e2e`) is deliberately **not** in `npm test -ws` / Verify; it runs in its own `.github/workflows/functional-test.yaml`, on PRs to `mainline`, independently of Verify (see the root CLAUDE.md's _Deployment_ section). Locally, `npm run build -ws` treats this package's `build` as the same `echo` no-op `core` uses — there's nothing to compile.
**Env.** `E2E_BASE_URL` (defaults to `http://localhost:5173`) — point it at a already-running instance (e.g. a deploy preview) to skip the `webServer` auto-start; `CI` — set by GitHub Actions, flips `retries` to 2 and `reuseExistingServer` to `false`.
