# packages/design

Package-specific guidance. See the repo-root `CLAUDE.md` for universal rules (commands, dependency graph, the _Legend_ of field labels, contributing). Italic cross-references name a section that may live in another package's `CLAUDE.md` — most app subsystems are in `packages/app/CLAUDE.md`.

**Purpose.** React UI primitives that emit Tailwind/DaisyUI class strings, previewed and published as a static Storybook site. App and www still compile the class strings for their own bundles — design's own tailwind/daisyui deps exist only to render Storybook.
**Where.** `src/index.ts` (re-exports), `src/components/*` (co-located `*.stories.tsx`), `src/tokens.css` (the consumer-importable shared token fragment — daisyui `nord` + `--font-sans`; no `@import "tailwindcss"`, since consumers already have one), `src/design.css` (the Storybook entry — `@import "tailwindcss"` + `@import "./tokens.css"`), `.storybook/` (`main.ts` + `preview.tsx`; `manager.ts` + `theme.ts` brand the manager shell from tokens — see _Gotchas_), `tsconfig.json`, `eslint.config.js`. See [`DESIGN.md`](DESIGN.md) for the long-form design system doc (color, typography, spacing, radii, components).
**Surface.** `ScreenH1–H5`/`ScreenP` (typography), `ErrorMessage` (migrated from app's `Error` — renamed on the move since `Error` shadows the JS global), `Hero`, `Screen`/`ScreenTwoCol` (layout containers — single- and two-column page wrappers, migrated from app's `component/screen`; distinct from the `Screen*` typography scale despite the shared name prefix), `InputText`, `InputDate`, `InputSelect`, `Textarea` (multi-line free-text input — mirrors `InputText`'s `value`/`onChange`/`onBlur`-to-commit shape but drops `align` and the Enter-to-blur `onKeyDown`, since a `<textarea>` needs Enter to insert a newline; commit is blur-only), `SearchBar` (a thin `InputText` wrapper — the first design component to import another via `@/`). `Modal`/`ModalTitle`/`ModalFooter`/`ModalScreen`/`useModal` (the `<dialog>`-backed modal family — `useModal` returns a ref + toggle handler; `ModalScreen` composes `ModalTitle`+`ModalFooter` as the standard body scaffold). `Popover` (a lightweight anchored info bubble — hover-to-open on desktop, tap-to-open on mobile, dismissed by outside click/blur/`Escape`; a plain `relative`/`absolute` React component rather than `<dialog>` or DaisyUI's native `popover` attribute, since neither gives hover-to-open, and it does no viewport-edge flipping). svg icons (`Hamburger`, `Plus`, `Pencil`, `Chevron`, `Cancel`, `Trash`, `UpDown`, `Minus`, `LockClosed`). `InputText` blurs on Enter when an `onBlur` handler is present — that's how "press Enter to commit" works app-wide. `DataGrid`/`DataGridRow`/`DataGridHeaderRow`/`DataGridSubheaderRow`/`DataGridLabel`/`DataGridLabelNote`/`DataGridInput`/`DataGridSelect`/`DataGridCheckbox`/`DataGridAddButton`/`DataGridAddRow`/`DataGridRemoveButton` (the dense editable-grid family used by batch planning and recipe editing — migrated from app's `component/data-grid`, default exports converted to named; app's 13 files are now re-export shims). `SrmAvatar` (the SRM beer-colour swatch, migrated from app's `component/srm-avatar` together with the `--color-beer-*` tokens it renders — see _Styling_; app's file is now a re-export shim). `Timeline` (the hand-rolled inline-SVG elapsed-time line for the brew timer — a fluid-width `<svg>` with square `<rect>` markers at proportional offsets; x-axis only, no y-axis data, no chart library. It stays dumb: `onMarkerHover`/`onMarkerClick` hand back the marker plus its `percent` along the line, and any `Popover` overlay is the consumer's to position — a `Popover` renders a `<div>` and so cannot be nested inside the `<svg>`. A running timer re-scales the line every tick, so `markerTransitionMs` transitions the marker `<rect>`'s **`x` geometry property** — CSS-animatable SVG geometry, not a `transform`, since the `x` is a percentage of the fluid width and a `transform` translate takes user units. Set it to the consumer's tick interval; leave it unset and markers jump).
**Invariants.** ⚠️ Class strings must be valid **DaisyUI v5 / Tailwind v4** — app and www are what compile them for the real app (via `@source "../../design/src"` + `@plugin "daisyui"`); Storybook compiles them too now, but only for its own preview. design now has a `@/*` → `./src/*` alias like app (`tsconfig.json`) — cross-component imports must go through it, since the shared eslint base bans `../` inside `src/**` (see _Linting_). ⚠️ design declares no `tailwindcss`/`daisyui` runtime dependency for consumers — `tokens.css`'s `@plugin`/`@theme` resolve against **the consumer's own** Tailwind pipeline (see _Styling_); adding those as design deps risks a second hoisted copy drifting from app/www's.
**Gotchas.** `.storybook/main.ts` wires the Tailwind v4 Vite plugin in explicitly via `viteFinal` — Storybook's bundled Vite instance doesn't auto-discover a project `vite.config.ts` (design has none), so without it `design.css`'s `@import`/`@plugin`/`@theme` directives would ship uncompiled. The same `viteFinal` also carries the `@/` alias's `resolve.alias` entry (mirroring `app/vite.config.ts`) — `tsconfig.json`'s `paths` only satisfies the type-checker, not Storybook's bundler. ⚠️ `main.ts` also **brands the manager (shell) from our tokens**: at config-load (Node) it reads `src/tokens.css` + daisyui's `nord` theme CSS, flattens the nord **oklch** palette to hex with `culori` (devDep — Storybook's `polished` opacifies several theme vars and throws on oklch), and writes `.storybook/tokens.generated.ts` (git-committed but **eslint-ignored**, like a `*.gen.ts`; regenerated deterministically each start). `theme.ts` builds the `create()` theme from that map — nord throughout, including the two `polished`-run accents (`colorPrimary`/`colorSecondary` = nord's Frost blue, matching the blue that dominates app/www) — and `manager.ts` applies it via `addons.setConfig`. ⚠️ Generation runs in Node because the **manager builder can't `import … ?raw`** (a Vite-only feature that works in the preview but not the shell); reading the CSS in the manager bundle instead throws at init and silently reverts to the default theme. `input-checkbox` and `input-unit` (dead, non-compiling stubs, never exported) were deleted — reintroducing either needs a real implementation, not the old stub.
**Example.** _None._
**Commands.** `npm run dev -w packages/design` (`dev:design` from root) — Storybook on `:6006`. `npm run build -w packages/design` (`build:design`) — static Storybook to `dist/`, what `build-test-deploy.design-prod.yaml` uploads.
